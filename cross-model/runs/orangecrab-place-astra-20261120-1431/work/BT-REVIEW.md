# Board-tool review

I used bt throughout this layout alongside pcbnew and KiCad's native DRC. Counts below are approximate except where a run is identified. I did not instrument token usage or run a timed control project.

| Command | Use on this job | Result |
| --- | --- | --- |
| board, part, query, length, help | Board inventory once, several part and measurement queries, command help repeatedly | The initial inventory exposed the unusual copper artwork, exposed areas, locked items and existing rule values before placement. Short queries were easier to review than repeatedly parsing the full board. |
| render | At each major milestone, including discarded attempts | Made it practical to compare where the memory, switch, power parts and escapes actually fit in a headless session. The combined views get dense under the BGA. Per-layer or cropped views are substantially clearer. |
| route | Two principal batches | The three regulator switch nodes took about three seconds and stayed short with no vias. An early memory batch finished only one of 23 nets in about 84 seconds. The default 0.127 mm neck limit and crowded exits on this 0.5 mm package restricted its usefulness. Specific blockers were more informative than the completion percentage. |
| pair | Two significant trials | In the USB trial, the positive leg reached the series resistor while the negative leg joined the duplicate USB-C contacts. The result reported success despite the 15.924 mm mismatch. A DDR strobe trial gave unequal via counts. I rejected both and generated explicit pad-to-pad paired routes. |
| plane, probe, apply | Roughly seventeen plane trials, several standalone probes and over twenty checked applications before timing work | Ground access increased from 234 to 245 of 264 candidate pads after moving the flash. These operations found legal short drops quickly, and probing prevented a collision at J6 and a sub-rule copper gap. In the eventual DDR-first layout, access dropped because signal routing already occupied many sites. A count of drops alone does not establish connectivity after refill. |
| fill, same, cleanup | Repeated fills, locked-part comparisons and a main cleanup pass | Saving fills before native DRC was essential. Cleanup removed 17 dead ends and 60 redundant segments, split 32 segments at junctions and removed about 20 mm of copper. KiCad subsequently found further dangling tracks and vias. I removed those on copies with connectivity checks after each pass. |
| tune, apply --checked | Individual memory-net trials followed by a combined, independently checked candidate | The per-net report distinguishes an exact result, partial length addition and no available space. Some proposed replacement paths include long stretches of existing copper. Checked apply objected to holes of laser vias on layers beyond the drill span, including GND at the lower-byte strobe. Native KiCad DRC on the proposed layout was necessary to distinguish that issue from an actual collision. |
 
I used pcbnew for the circuit-aware floorplan, capacitor placement, HDI via geometry, zone construction and pin-to-pin measurements. I tried a local headless Freerouting session as a comparison. I kept a different DDR-first layout and used a local multilayer path search with explicit through, laser and buried via choices to complete its connections. That let me control which BGA routes and power regions could be displaced. The saved intermediate boards, refusal to overwrite a changed board and independent native DRC were valuable during repeated attempts.

I would prioritize explicit endpoint pairs on both differential legs, distinct reporting of matched branch paths and total net copper, and drill checks that use the physical layer span for all via types. For planes, report how many pad groups still need a connection after refill alongside the number of new drops. For dense digital layouts, let a bus specify the source and sink pins, stack-dependent via length, preferred reference and permissible tuning area. A fab-profile setting would also make the generic 0.127 mm threshold meaningful on boards designed around a documented finer process.

On the completed six-layer geometry, `bt check OrangeCrab.kicad_pcb` exited 2 after 14 seconds with “Maximum call stack size exceeded”. It produced no check summary. I ran KiCad's DRC on a saved, refilled board and exported Gerber and drill files directly. `bt islands --net GND` helped locate U3.G17 when a candidate timing change isolated it. On the same board its fill-age heuristic flagged vias on layers outside their physical span. A stack-aware check would remove those false positives.

Running the same JavaScript entry point with a larger Node stack let the combined check finish. It agreed with KiCad on the two fixed-footprint errors, 201 original warnings and zero unconnected items, and reported zero nets in pieces. It applied the 0.15 mm through-drill minimum to the 0.10 mm laser vias and suggested resizing them, despite the project’s separate 0.10 mm microvia drill rule. It also flagged sub-0.127 mm tracks, consistent with its documented generic threshold. Resizing either feature indiscriminately would break the FPGA breakout.

On the final file the combined check finished in 29 seconds with the larger stack and confirmed the stored fills were current. The two supplemental findings covered 197 laser vias and 4,678 fine-width track segments. I made roughly forty individual tuning trials, inspected A/B board copies at 21 visual milestones, and used islands twice on the difficult FPGA/DRAM ground connections. The counts describe actual use on this board; they are not performance benchmarks.
